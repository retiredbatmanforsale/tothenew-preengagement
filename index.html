Dimension 1 · The plan

Ten days to working AI‑native engineers.

One shared spine, hands-on heavy, role-forked only where it must be (Day 8). Each day moves the cohort one capability forward — from "I autocomplete with Copilot sometimes" to "I ship features end-to-end with an agent I supervise." The arc compounds; later days depend on earlier ones landing.

Open questions before we lock the curriculum.

Decisions that, once answered, move this from a proposal into an executable plan. None block design work; all block delivery.

    Dimension 2 · The proof

    A dashboard that defends the training.

    Activity, throughput, adoption, and quality — measured continuously, segmented by engineer and team, so leadership can see the curve. Below is the scaffold. Live metrics come online once instrumentation is wired into TTN's repos, IDEs, and ticketing.

    Status · Pre-engagement baseline phase

    The metric scaffold is designed but no measurements have flowed yet. We need (a) a two-week pre-training baseline against the same metrics so the after-picture has something to compare against, and (b) license access + telemetry wiring before Day 1.

    Engagement phase
    Baseline · Train · Adopt · Sustain

    Audit Google's internal AI-adoption tracking method.

    A research task before we lock the metric set. Google has published partial methodology (DORA + DX-style internal surveys, agent-touch ratios on CLs). We adopt what's load-bearing and skip the rest. Output: a one-page comparison + the final metric list.
